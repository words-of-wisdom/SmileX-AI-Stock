# 修复：开盘后大盘/板块AI分析一直显示昨天的数据

## 根因（三层叠加）

1. **早盘任务今天未部署**（一次性）：`analysis.morning_generate`（9:20）是今天上午 11 点后才注册的新任务，9:20 时服务里还没有它 → 当天无 morning 记录，前端只能展示昨天 close 报告。明天起会正常触发。
2. **LLM 422 敏感词无降级**（持续性风险）：morning 分析把近 24h 资讯**原文**注入 prompt（`_collect_recent_news`），MiniMax 内容审核命中敏感词（`input new_sensitive (1026)`）直接 422 拒绝整个请求 → 分析 failed。资讯是外部抓取的不可控内容，明天 9:20 自动跑时大概率复现。
3. **任务失败无补跑**（持续性风险）：`_generate_for_types` 去重条件是"当天已有**任意**记录（含 failed）则跳过"，且 cron 是单点触发（`20 9`）→ 当天一旦失败，全天无早盘数据。

顺带发现的独立 bug：`strategy.trade_engine` 的 cron 写了 8 个字段（`* * * * * 9-15 * * mon-fri`），`CronTrigger.from_crontab` 解析失败被 `_build_trigger` 吞掉只记日志 → **交易引擎 job 从未注册、从未执行过**（DB 里 last_run_at=None 证实）。

## 修改内容

### 1. `backend/modules/analysis/services/analysis_executor.py` — LLM 失败降级重试（核心）

- `_collect_market_data` / `_collect_sector_data`：移除内部的资讯注入块（两处 try `_collect_recent_news`）
- `_analyze`：资讯单独收集（保留原 try/except 不阻塞语义），LLM 调用改为带降级的两段式：
  - 首次调用：行情数据 + 资讯段（行为与现在一致）
  - 首次抛异常且注入了资讯 → **去掉资讯段重试一次**，替代段注明"近24小时资讯暂缺（内容审核原因未注入，请在报告中注明消息面数据缺失）"，日志 warning 记录降级原因
  - 无资讯或二次仍失败 → 按原逻辑抛出，`_execute_analysis` 标 failed

### 2. `backend/modules/scheduler/tasks/analysis_run.py` — 失败补跑

- 去重条件从"已有任意记录"改为 `status.in_(("success", "running"))`——failed 不阻塞当天重试（running 存在仍跳过，防并发；600s 超时最晚 9:30/16:15 定格，能被补跑点接住）
- cron 补跑点：morning `20 9` → `20,35 9`；close `5 16` → `5,25 16`（成功后第二轮被去重跳过）
- 同步更新任务 description 与文件头注释

### 3. `backend/modules/scheduler/tasks/strategy_run.py` — 修非法 cron

- trade_engine：`* * * * * 9-15 * * mon-fri` → `* 9-15 * * mon-fri`
- 启动时 `sync_registry_to_db` 会用代码定义覆盖 DB 并重建 job，重启即生效
- ⚠️ 行为变化：修好后交易引擎将首次真正开始每分钟执行（待执行信号的模拟买卖/止损止盈平仓），请知悉

### 前端：不改

报告面板已有 running 轮询、failed 状态与错误信息展示、手动生成按钮；补跑成功后 `latest` 接口（按 created_at desc 取最新）自然返回新记录。

## 验证步骤

1. 重启后端（需你配合或告知我重启方式）→ 检查日志无"构建触发器失败"，`sys_scheduled_task` 中 morning cron 已更新、trade_engine `next_run_at` 非空
2. 手动触发 market + sector 的 morning 分析各一次 → 确认成功落库（顺带补上今天缺失的早盘报告，页面立即可见今天数据）
3. 保留现场：今天 11:47 那条 failed 记录会留在历史里，属预期
