# 股票热榜：定时刷新生效 + 数据补全

## 诊断结论（已核实代码）

**问题1「没有定时刷新」**：定时任务本身在跑（`*/5 9-15 * * mon-fri` + 交易时段守卫），但入库用 `on_conflict_do_nothing`（`backend/modules/stock/services/stock_hot_service.py:94-96`）——联合唯一键 `(record_date, source, stock_code)` 使得当日首次同步后，后续同步只追加新上榜个股，**从不更新已有行的排名/价格**，掉榜股票也不移除。页面数据停留在当天第一次抓取时点。

**问题2「数据不完整」**（按源确认的整列空洞）：
- `xq_follow`/`xq_tweet`：**涨跌幅**恒 null——akshare `stock_hot_xq.py` 只返回 代码/简称/关注/最新价 4 列（已查证源码）
- `ths_hot`：**最新价**恒 null——同花顺接口只解析 code/name/order/rise_and_fall/rate
- `em_rank`：**热度值**恒 null——东财 `getAllCurrentList` 只用了 sc/rk 两个字段

## 实施步骤

### 1. 实施前诊断（验证运行时状态）
- 实测东财 `getAllCurrentList` 原始返回（curl，pageSize=5）：若含热度字段则直接采用真实值，跳过步骤 4 的合成指数
- SQL 查 `sys_scheduled_task`（stock_hot.sync_all 的 status/next_run_at）与 `business_stock_hot_sync_log` 近期记录，确认任务在触发、各源是否失败

### 2. 修复「不刷新」：sync_all 改为滚动更新（`stock_hot_service.py`）
- `on_conflict_do_nothing` → `on_conflict_do_update`：冲突时更新 `rank / stock_name / latest_price / change_pct / hot_value / updated_at`
- 新增掉榜清理：upsert 后删除当日该源 `stock_code NOT IN (本次抓取代码集)` 的行（与现有"删前缀脏数据"同风格硬删，只影响当日）
- sync_log 的 `saved_count` = upsert 影响行数（语义变为"本次处理条数"）
- 「排名变化」语义保持现状 = 相对上一交易日快照，无需改查询层

### 3. 修复「不完整」：fetcher 统一行情补全（`stock_hot_fetcher.py`）
- 新增 `_fill_quotes(client, items)` 后处理：收集 `latest_price` 或 `change_pct` 为 None 的代码 → 按首位映射新浪前缀（6→sh、4/8→bj、其余→sz，与前端 `openStockPage` 一致）→ 复用 `fetch_spot_quotes`（`_sina.py`）批量补 name/latest_price/change_pct，**只填空缺不覆盖源站原值**；失败仅 warning 不阻断
- `_fetch_xq`、`_fetch_ths_hot` 应用该补全；`_fetch_em_rank` 重构复用同一函数

### 4. 东财热度兜底
- 若步骤 1 实测无热度字段：`_fetch_em_rank` 填 `hot_value = 101 - rank`（合成热度指数），代码注释说明

### 5. 时间窗微调（`stock_hot_sync.py`）
- 下午交易窗守卫延到 15:05（cron `*/5 9-15` 本就含 15:05 触发），补抓最终收盘快照

### 6. 顺带小修
- `backend/modules/agent/tools/stock_tools.py` `get_hot_stocks` 的 source 参数描述改为真实 key（em_rank/ths_hot/xq_follow/xq_tweet），当前写的是 eastmoney/10jqka/xueqiu，传错即"来源不存在"

### 7. 验证
- 手动 `POST /admin/stock/stock-hot/sync` 两次，SQL 确认同日第二次同步后 rank/price 被更新、掉榜行被删
- 检查雪球榜涨跌幅、同花顺榜最新价已填充
- 任务日志 saved_count 稳定 ≈100（滚动更新后每源每次都是全量 upsert）
