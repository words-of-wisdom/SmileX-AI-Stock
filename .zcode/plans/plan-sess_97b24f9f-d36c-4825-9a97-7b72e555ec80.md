# A股数据补拉 + 定时同步可靠性修复

## 背景诊断（已确认）

定时任务本身在正常运行（今天 15:30/31/35/40 均触发）。数据缺失的真实原因：
1. **东财 push2 对本机 IP 限流**（RemoteDisconnected）：大盘资金流、板块资金流、暗盘每日统计今日未入库（均为东财单源，无兜底）；指数快照/板块列表走了新浪/腾讯兜底已入库。
2. **代码 bug**：`BlockTradeService.sync_active` 未分块 upsert，暗盘"近六月"（1800+ 行 × 18 列）超过 asyncpg 32767 参数上限，持续失败。

## 改动内容

### 1. 新建一次性补数脚本 `backend/scripts/sync_astock_latest.py`

参照 `scripts/cleanup_duplicate_sessions.py` 模式（sys.path 处理 + asyncio.run），用 `ENVIR=dev cd backend && .venv/bin/python -m scripts.sync_astock_latest` 运行：
- `database.db_manager.init_pool()` 初始化，`database.manager.async_manager.get_session()` 取会话（与 scheduler 任务同一模式）
- 依次执行，步骤间 sleep 错开请求：
  1. `MarketService.sync_all` — 指数快照 + 大盘资金流（东财单源，失败后间隔 30s 重试 2 次）
  2. 对 7 个跟踪指数调 `MarketService.get_history(days=90)` 触发历史回补（东财失败自动降级 **baostock 日线**，收盘后数据已就绪）
  3. `BoardService.sync_all("industry")` / `("concept")` — 板块列表 + 资金流
  4. `LimitUpService.sync_all` — 涨停股池
  5. `BlockTradeService.sync_all` — 暗盘每日统计 + 三窗口活跃股
- 每步打印 fetched/saved，结束打印汇总；如实报告仍拉不到的数据（东财若仍限流）

### 2. 修复 asyncpg 32767 参数上限 bug

`backend/modules/stock/services/block_trade_service.py`：`sync_active` 与 `sync_daily` 的批量 upsert 改为分块执行（每批 ≤800 行），累加 rowcount，行为/返回值不变。近六月数据恢复同步。

### 3. 资金流抓取加退避重试（小改动）

`market_fetcher.fetch_market_fund_flow` 与 `board_fetcher.fetch_board_fund_flow` 内加 1 次重试（间隔约 20s），让下周一 15:30 的定时任务在瞬时被限流时有机会自愈。

### 4. 按仓库规则写业务记忆

新增 `aiDoc/memory/business/2026-08-14_astock_sync_diagnosis_and_fix.md`（按 TEMPLATE.md），并同步更新 `aiDoc/memory/business/README.md` 与 `aiDoc/memory/project-memory.md` 索引。

## 验证

- 运行补数脚本，确认输出各模块 fetched/saved > 0（东财单源项视限流情况如实汇报）

- 无需数据库迁移（纯代码修复，不改表结构）
